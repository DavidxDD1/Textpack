## 案例 1：采用完整容器大小计算收益

如果只统计 Huffman 有效位流，`banana` 的9位码流看起来很小，但文件必须携带原始大小、频率表与校验值。实现把固定18 B文件头、每符号5 B频率表及字节补齐计入统计。实际6 B输入生成35 B文件，UI显示负收益。这个取舍由 Codex 实施，未写成学生自行提出的修改。

## 案例 2：处理 Unicode 与原始文本差异

Python 按码点索引，JavaScript 默认按 UTF-16 单元索引，因此 emoji 会造成跨层下标差异。前端采用 `Array.from` 进行高亮。代码审查还发现 textarea 会规范化换行，于是增加独立的原始文本状态；用户未编辑时保留导入内容的 CRLF 和 BOM。真实浏览器测试导入 BOM+CRLF 样例、下载压缩文件，再用 CLI 解压并比较原始字节，结果一致。

## 案例 3：真实失败推动窄屏修复

第一次浏览器测试在 `Mobile layout has no horizontal overflow` 断言失败。原因是网格项目的最小内容宽度让表格撑开390 px视口。随后为卡片和网格设置 `min-width:0`，并限制滚动容器宽度；再次运行13项浏览器检查全部通过。最终截图来自修复后的真实页面，没有绘制测试结果或伪造截图。

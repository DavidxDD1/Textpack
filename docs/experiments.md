# 数据与实验说明

实际记录时间（UTC）：2026-10-19T20:04:53.823698+00:00。环境：Windows-11-10.0.22631-SP0，Python 3.12.14。

## 1. 数据来源

全部示例由本项目合成，不引用真实个人笔记或外部数据集。`study_notes.txt` 含24段结构相同、序号不同的算法学习记录，文件用 UTF-8、LF 换行保存，共4,882个码点、12,288字节。重复内容使其适合展示压缩收益，但不能代表所有现实文本。

`overlap.txt` 为 ASCII 文本 ababab；`tiny.txt` 为 banana；均无末尾换行。实验另构造空字节串、0到255各出现一次的字节串，以及 Random(2026) 生成的4,096字节数据。随机数据是固定种子的伪随机序列，不称为不可预测的密码学随机数。

## 3. KMP 与朴素匹配

输入为 n 个 a，模式为63个 a 后接一个 b。两种算法均返回空结果。比较计数通过字符串字符包装器拦截 ==/!= 操作获得；KMP 的次数含构造前缀函数。计时使用未包装的普通字符串，运行5次取中位数。

| n | m | KMP 比较次数 | 朴素比较次数 | KMP 中位 ms | 朴素中位 ms |
| --- | --- | --- | --- | --- | --- |
| 2000 | 64 | 6122 | 123968 | 0.1757 | 3.5594 |
| 4000 | 64 | 12122 | 251968 | 0.352 | 7.2925 |
| 8000 | 64 | 24122 | 507968 | 0.6963 | 14.74 |
| 16000 | 64 | 48122 | 1019968 | 1.3519 | 29.8053 |

本实验故意选取大量重复前缀失配的输入。m 固定时两列次数都随 n 近似线性增长，因此不能把此表单独当作 O(n+m) 对 O(nm) 的一般证明；渐近结论来自算法分析。计时只描述本次环境，不保证换机重现相同毫秒数，也不意味着纯 Python KMP 一定快于采用底层优化的 str.find。
